# План реализации главного экрана Todo приложения

## Контекст

Пользователь запросил создание главного экрана для приложения Списки дел со следующими требованиями:
- Профиль пользователя
- Меню из страниц с формой для добавления новой страницы
- На каждой странице свои списки дел с полем для добавления нового списка
- В каждом списке задачи с полем для добавления новой задачи

**Текущее состояние:**
- ✅ Backend полностью готов: NestJS + Prisma с JWT авторизацией
- ✅ Все CRUD API эндпоинты реализованы (Pages, Lists, Tasks)
- ✅ Frontend: Next.js 15, Material-UI, React Hook Form, Zod, Axios
- ✅ Аутентификация полностью реализована (LoginForm, RegisterForm, useAuth)
- ✅ Типы данных определены в @todo-app/shared
- ❌ Главная страница — только заглушка

**Иерархия данных:** User → Page → List → Task

**Причина изменения:**
Необходимо создать полнофункциональный интерфейс для работы со списками дел. Сейчас пользователь может только войти/зарегистрироваться, но не может управлять своими задачами. Нужно реализовать полный CRUD функционал для всей иерархии (страницы → списки → задачи) с удобным визуальным интерфейсом.

## Архитектурный подход

Следуем Feature-Sliced Design (FSD), как в существующей feature `auth`:

```
features/
├── pages/     # Управление страницами
├── lists/     # Управление списками
└── tasks/     # Управление задачами
```

Каждая feature содержит:
- `api/` — API вызовы через axios
- `model/` — React хуки для управления состоянием
- `ui/` — React компоненты
- `index.ts` — публичные экспорты

## Структура компонентов

```
MainTodoPage (apps/frontend/src/app/page.tsx)
├── TopAppBar
│   ├── Название приложения
│   ├── Профиль пользователя (имя/email)
│   └── Кнопка выхода
├── PagesSidebar (280px слева)
│   ├── Кнопка "Новая страница"
│   └── Список страниц (выбор, редактирование, удаление)
└── TodoWorkspace (основная область)
    ├── Заголовок выбранной страницы
    ├── ListsContainer (горизонтальная прокрутка, стиль Trello)
    │   ├── ListCard (для каждого списка)
    │   │   ├── Заголовок списка (редактирование, удаление)
    │   │   ├── TaskItem (чекбокс, название, описание, действия)
    │   │   └── Кнопка "Добавить задачу"
    │   └── Кнопка "Добавить список"
    └── EmptyState (когда нет выбранной страницы)
```

## Критические файлы для изменения

### Новые features (по порядку создания)

1. **`features/pages/api/pagesApi.ts`** — API для страниц (getAll, create, update, delete)

2. **`features/pages/model/usePages.ts`** — Хук управления состоянием страниц, автозагрузка при монтировании

3. **`features/pages/ui/PagesList.tsx`** — Sidebar со списком страниц, диалоги создания/редактирования

4. **`features/lists/api/listsApi.ts`** — API для списков (getAll с pageId, create, update, delete)

5. **`features/lists/model/useLists.ts`** — Хук управления списками, зависит от выбранной страницы

6. **`features/tasks/api/tasksApi.ts`** — API для задач (getAll с listId, create, update, delete)

7. **`features/tasks/model/useTasks.ts`** — Хук управления задачами, метод toggleTask для чекбокса

8. **`features/tasks/ui/TaskItem.tsx`** — Компонент задачи: чекбокс, название, описание, кнопки редактирования/удаления, диалог редактирования

9. **`features/lists/ui/ListCard.tsx`** — Карточка списка: заголовок, список задач, форма добавления задачи

10. **`features/lists/ui/ListsWorkspace.tsx`** — Контейнер всех списков с горизонтальной прокруткой, кнопка добавления списка

11. **`shared/ui/AppBar.tsx`** — Верхняя панель: название приложения, профиль пользователя (загрузка через authApi.getCurrentUser), меню выхода

12. **`shared/ui/EmptyState.tsx`** — Универсальный компонент пустого состояния (иконка, текст, кнопка действия)

13. **`app/page.tsx`** — Главная страница: layout с drawer для sidebar, интеграция всех компонентов, обернуто в ProtectedRoute

### Обновляемые файлы

14. **`features/pages/index.ts`** — Экспорты pagesApi, usePages, компонентов UI

15. **`features/lists/index.ts`** — Экспорты listsApi, useLists, компонентов UI

16. **`features/tasks/index.ts`** — Экспорты tasksApi, useTasks, компонентов UI

17. **`shared/ui/index.ts`** — Экспорты TopAppBar, EmptyState

18. **`shared/index.ts`** — Реэкспорт всех shared компонентов

## Используемые существующие функции

- **`@/lib/api.ts`** — Axios instance с JWT interceptor (автоматически добавляет Bearer token)
- **`@/features/auth/model/useAuth`** — Хук для logout функциональности
- **`@/features/auth/api/authApi.getCurrentUser()`** — Получение данных текущего пользователя
- **`@/shared/ui/ProtectedRoute`** — Обертка для защищенных роутов
- **`@todo-app/shared`** — Типы: Page, List, Task, CreatePageDto, UpdatePageDto и т.д.

## UX особенности

### Управление состоянием
- Локальный state через useState для UI состояния (выбранная страница, режим редактирования)
- Кастомные хуки (usePages, useLists, useTasks) для серверного состояния
- Автоматическая загрузка данных через useEffect
- Ручная перезагрузка после мутаций

### Адаптивность
- **Desktop (>1024px)**: Sidebar 280px слева, горизонтальные карточки списков
- **Mobile (<768px)**: Drawer для sidebar, вертикальные карточки списков
- useMediaQuery(theme.breakpoints.down('md')) для определения мобильного устройства

### Inline редактирование
- Двойной клик или кнопка Edit для редактирования заголовков
- Enter для сохранения, Blur для автосохранения
- Диалоги Material-UI для сложных форм (с описанием задачи)

### Пустые состояния
- "Выберите страницу" — когда не выбрана страница
- "Нет списков" — когда в странице нет списков
- Понятные призывы к действию (CTA кнопки)

### Обработка ошибок
- Отображение ошибок через state в хуках
- Alert компоненты Material-UI для критичных ошибок
- Graceful degradation при проблемах с сетью

## Порядок реализации

1. **Создать features структуру** — api/ и model/ слои для pages, lists, tasks

3. **Создать UI компоненты** — TaskItem → ListCard → ListsWorkspace → PagesList
4. **Интегрировать в главную страницу** — Обновить app/page.tsx с полным layout
5. **Создать index файлы** — Настроить экспорты для всех features

## Проверка работоспособности

После реализации протестировать:

1. **Запуск приложения**:
   ```bash
   npm run dev
   ```

2. **Авторизация**: Войти через /login или зарегистрироваться через /register

3. **CRUD страниц**:
   - Создать новую страницу
   - Переименовать страницу
   - Удалить страницу

4. **CRUD списков**:
   - Выбрать страницу
   - Создать список
   - Переименовать список
   - Удалить список

5. **CRUD задач**:
   - Добавить задачу в список
   - Отметить задачу как выполненную
   - Редактировать название и описание
   - Удалить задачу

6. **Адаптивность**:
   - Открыть DevTools и проверить мобильное отображение
   - Проверить работу drawer на мобильных устройствах

7. **Обработка ошибок**:
   - Остановить backend и проверить отображение ошибок
   - Проверить работу токена и редирект на /login при 401
